
## Различия команд анализа:
* git log — показывает общую ленту новостей (историю коммитов: кто, когда и зачем).
* git diff — показывает текущие изменения в коде прямо сейчас (разницу между состояниями).
* git show — открывает конкретный коммит «под микроскопом» (показывает его автора и весь его код).

## Результаты поиска:
* git log -S"def" — нашел коммит, в котором код переписали на функции (момент, когда слово "def" впервые появилось в файле).
* git blame — показал «авторство» каждой строчки калькулятора (кто конкретно написал этот кусок кода).

## Различия команд восстановления:
* git restore — сбрасывает все текущие несохраненные правки и возвращает файл к состоянию последнего коммита.
* git restore --source=... — временно вытаскивает в рабочую папку версию файла из любого старого коммита.

## Что произошло бы с правками:
* Если бы мы случайно закоммитили испорченный файл, наши старые правки (функции вычитания и умножения) стерлись бы из актуальной версии кода, и их пришлось бы вручную доставать из истории репозитория через старые коммиты. При обычном git restore незакоммиченные правки просто безвозвратно удаляются.

## Разница между revert и reset --hard:
* git revert — это «безопасный ластик». Он оставляет ошибочный коммит в истории, но создает новый коммит поверх него, который просто возвращает код назад.
* git reset --hard — это «машина времени со сносом истории». Он буквально удаляет коммиты из истории, возвращая репозиторий в прошлое состояние, как будто ошибки никогда не было.

## Почему в опубликованной истории безопаснее revert:
* Если мы уже отправили (push) коммиты на GitHub, другие разработчики могли их скачать. 
* git revert просто добавит новую историю поверх старой, и у всех всё обновится без конфликтов.
* git reset --hard перепишет историю. Если её отправить на сервер (через force push), у других разработчиков всё сломается, так как их Git не поймет, куда пропали прошлые коммиты.

## Чем тег отличается от ветки:
* Ветка — это «живой указатель». Она постоянно двигается вперед вместе с вами, когда вы делаете новые коммиты.
* Тег — это «застывший снимок». Он навсегда привязан к одному конкретному коммиту (как закладка в книге) и никогда не сдвинется сам, сколько бы коммитов вы потом ни сделали.
